# Support and maintainer response policy

Vibesboard is maintained on a best-effort basis while it is in public beta.
There is no paid support plan, uptime guarantee, or guaranteed response time for
community questions.

## Where to ask

- Use GitHub Discussions for setup questions, configuration help, and design
  discussion.
- Use a GitHub issue for a reproducible bug or a focused feature request. Please
  use the issue templates and include the version or commit, environment, and
  reproduction steps.
- Use the private process in [`SECURITY.md`](SECURITY.md) for vulnerabilities.
  Never include credentials, customer data, or an exploitable security report in
  a public issue.

## Best-effort targets

Maintainers aim to acknowledge a new issue or discussion within **5 business
days**, triage a reproducible bug within **10 business days**, and provide a
first review on a complete pull request within **10 business days**. These are
targets, not service-level commitments; security reports follow the separate
acknowledgement and assessment targets in [`SECURITY.md`](SECURITY.md).

Issues and pull requests may be closed when they are duplicates, lack the
requested reproduction details after a reasonable follow-up, conflict with the
project boundary, or have been inactive for 60 days. Closing an issue does not
prevent a new report when circumstances or evidence change.

## Compatibility and releases

The project is pre-1.0. Follow [`ROADMAP.md`](ROADMAP.md) and the latest release
notes for the current support boundary. There are no long-term support branches
or backports to old commits; fixes target `main` and are released from there.
