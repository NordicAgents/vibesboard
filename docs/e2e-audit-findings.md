## Open: `~~~agentcreated~~~` never reaches the creator chat

Found by making the `create_agent` tool path reachable (the mock now emits a tool
call when a prompt contains `E2E_TRIGGER_CREATE_AGENT`). **The agent row is
written, but the HTTP response body is empty**, so the UI is told nothing.

- `app/api/agent-creator/route.ts` ends with `result.toTextStreamResponse()`,
  which streams text parts only, and sets no `maxSteps`. In AI SDK v4 that means
  one step: the model emits a tool call, `tool.execute()` runs and inserts the
  agent, and the string it returns — carrying `~~~agentcreated~~~` and the new
  id — is a *tool result*, never converted into assistant text.
- `components/agents/agent-creator-chat.tsx` uses `streamProtocol: 'text'` and
  parses `~~~agentcreated~~~` out of the finished message in `onFinish`. With an
  empty stream that regex never matches, so no success screen and no redirect.

Verified twice — once on `ai@4` and again after the `ai@7.x` /
`@ai-sdk/openai@4.x` upgrade: a triggered request returns a body of length 0
while `select … from agents` shows the new row. Not fixed here — the repair is
either a second step (making the marker depend on the model echoing a tool
result, i.e. fragile) or moving to `toDataStreamResponse()` and changing the
client's stream protocol. Both need validating against a real model, not the stub.

Note for whoever picks this up: `@ai-sdk/openai@4.x` targets `/v1/responses`,
not `/chat/completions`. `e2e/mock-openai.mjs` now emits tool calls on **both**
endpoints, so the path stays reachable whichever the provider is configured for.
`e2e/local/01-agent-creation.spec.ts` asserts the persistence half and documents
the gap inline.

Fixed during the session (listed here for completeness, no action needed):
- `04-llm-providers` delete test deleted the *oldest* provider and asserted only on a toast role react-hot-toast never renders — rewritten to target its own provider by accessible name and verify removal server-side.
- `04-llm-providers` task-routing test silently `test.skip()`ed every run — now guarantees its precondition and asserts all four rows.
- `11-tenant-flow` workspace-switcher test clicked the account menu — app now gives the two controls distinct accessible names.

### `00-smoke.spec.ts` — The 'pointed at the local test server' config guard is a tautology and never reads the Playwright config
**kind:** vacuous-test  
Line 57 asserts `new URL(BASE_URL).port === (process.env.E2E_APP_PORT ?? '3100')`. But BASE_URL is itself built from that same env var: constants.ts:2-3 do `APP_PORT = Number(process.env.E2E_APP_PORT ?? 3100)` and `BASE_URL = http://localhost:${APP_PORT}`. Both sides of the expect are the same expression, so the assertion is true by construction for every value of E2E_APP_PORT (the only way to fail it is a non-canonical numeric string like '03100'). Worse, it does not test what its name claims: the thing that actually decides where the suite points is playwright.local.config.ts, which HARD-CODES `const APP_PORT = 3100` (line 15), derives its own BASE_URL (line 17) and sets `use.baseURL` (line 100) — it never imports constants.ts's BASE_URL and never reads E2E_APP_PORT. So the exact drift this guard exists to catch (constants.ts saying 3001 while the browser fixture navigates to 3100, or vice versa) leaves the test green. It also cannot detect 'the manual dev server': `reuseExistingServer: true` (playwright.local.config.ts:122) means whatever is already listening on 3100 is silently adopted, mock-OpenAI wiring and all.

**Evidence:** spec: apps/web/e2e/local/00-smoke.spec.ts:56-58 | source of both operands: apps/web/e2e/constants.ts:2-3 | config that actually drives navigation: apps/web/playwright.local.config.ts:15-17, :100 (`baseURL: BASE_URL`), :122 (`reuseExistingServer: true`)

**Suggested fix:** Assert against the real config surface instead of re-deriving the same constant: take `baseURL` from the test fixture (`test('...', async ({ baseURL }) => { expect(baseURL).toBe(BASE_URL) })`) so a divergence between playwright.local.config.ts and constants.ts fails. To also prove it is the E2E server and not a hand-started dev server, add an assertion that the app is talking to the mock model — e.g. hit an app route that reports the configured OPENAI_BASE_URL, or assert a request to localhost:4010 is observed during the chat smoke path.
